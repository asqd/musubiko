# Musubiko

Git-клиент под наш процесс: показывает ветки и то, как каждая из них соотносится с master и
develop, сравнивает ветки как GitHub и создаёт ветки hotfix flow одной кнопкой. Ядро написано на
Rust, приложение — на Tauri (веб-интерфейс внутри нативного окна). Сначала собираем под macOS,
потом тот же код соберём для Windows и Linux.

## Что уже есть

- Список веток: локальные и на `origin`, автор, последний коммит, сколько коммитов впереди и
  позади базовой ветки, что не запушено.
- Статус слияния с выбранной базой (develop или master):
  - **слита** — все коммиты ветки уже в базе;
  - **слита · squash** — коммиты другие (squash или rebase), но всё содержимое уже в базе;
  - **конфликт** — слияние с базой даст конфликт, со списком файлов;
  - **не слита** — в ветке есть то, чего нет в базе.
- Хотфиксы всегда сравниваются со своей базой: `hotfix/X` с master, `hotfix/X-dev` с develop.
  Пара показывается рядом.
- Фильтры (мои, не слиты, слиты, конфликт, старые, не запушены), поиск по `/`, обновление по
  ⌘R и при возвращении в окно.
- Дифф ветки как в pull request — от точки, где она отошла от базы: дерево файлов, unified и
  split, подсветка синтаксиса и изменённой части строки, разворот скрытых строк, «Просмотрено»,
  скрытие пробельных изменений. Дифф отдельного коммита. Для веток с конфликтом — сами места
  конфликта: что в базе и что в ветке. Клавиши: `j`/`k` — следующий/предыдущий файл, `v` —
  просмотрено, Esc — назад.
- «Новый hotfix»: из «LT-4900 ошибка в ваучере» делает `hotfix/LT-4900-oshibka-v-vauchere` от
  свежего `origin/master` и `hotfix/LT-4900-oshibka-v-vauchere-dev` от свежего `origin/develop`,
  проверяет, что имена свободны и на сервере, пушит обе. Если есть незакоммиченные изменения,
  по умолчанию открывает hotfix в соседней папке (worktree), можно вместо этого убрать
  изменения в stash и переключиться. Перед запуском видны точные команды; на ошибке можно
  повторить шаг, откатить или оставить как есть.
- Радар хотфиксов: по каждой паре видно, какие коммиты master-части уже есть на стороне
  develop (найденные по patch-id, то есть и после cherry-pick, или по содержимому — после
  squash), а какие нет. Отдельная тревога — коммиты, которые есть в master и нет в develop.
  Недостающее переносится кнопкой: cherry-pick во временной папке, при необходимости с созданием
  `-dev` ветки. Завершённые пары можно удалить.
- Журнал: всё, что приложение делало с репозиторием, с командами и отменой.

## Как устроены операции

Изменения в репозитории делает ядро, по одному шагу. После каждого шага оно записывает, как его
отменить, по тому, что получилось на самом деле: хэш новой ветки, запись stash. Отмена
проверяет, что с тех пор ничего не поменялось: ветку, в которой появились коммиты, не удалит;
ветку на сервере удаляет через `push --force-with-lease`, то есть только если там всё ещё то,
что запушили; stash вернёт, только если сверху лежит тот же. Журнал хранится в
`~/Library/Application Support/app.musubiko.Musubiko/journal.json`.

План — [docs/PLAN.md](docs/PLAN.md).

## Как считаются статусы

Все операции идут через git CLI, поэтому работают ваши настройки, хуки и доступы. Чтение не
берёт блокировку индекса (`GIT_OPTIONAL_LOCKS=0`) и не мешает git в терминале.

- Базой служит ветка с сервера (`origin/develop`), если она есть: «слита» значит слита там, куда
  мержат все. Если локальный develop отстаёт, это видно отдельно.
- Впереди/позади: `git rev-list --left-right --count base...branch`.
- Слияние проверяется в памяти через `git merge-tree --write-tree`: рабочая копия и индекс не
  меняются. Если результат слияния совпадает с деревом базы, всё содержимое ветки уже там — так
  находятся squash- и rebase-слияния, которые не видит `git branch --merged`.
- Автор ветки — автор её первого собственного коммита: git не хранит, кто создал ветку.

Нужен git 2.38 или новее (из-за `merge-tree --write-tree`). Приложение само выбирает самый
свежий git из `$MUSUBIKO_GIT`, `$PATH`, `/opt/homebrew/bin`, `/usr/local/bin` и `/usr/bin`.

## Структура

```
core/
  musubiko-core/     ядро: чтение веток, статусы слияния, flow (master/develop/hotfix)
  musubiko-cli/      утилита `musubiko`: то же, что показывает приложение, в терминале
apps/desktop/        приложение: React + TypeScript (src/), Tauri (src-tauri/)
design/              иконка: скрипт отрисовки и мастер 1024 × 1024
docs/PLAN.md         план разработки
```

## Сборка

Нужны Rust (1.88+), Node.js 20+ и Xcode Command Line Tools.

```bash
make test     # тесты ядра на временных репозиториях
make dev      # приложение с горячей перезагрузкой интерфейса
make run      # Release-сборка Musubiko.app и запуск
make icon     # перерисовать иконку из design/make-icon.swift
```

Готовое приложение: `target/release/bundle/macos/Musubiko.app`. Оно не подписано: при первом
запуске откройте его через контекстное меню Finder → «Открыть».

Утилита командной строки:

```bash
make branches REPO=~/work/project            # ветки против develop (или master, если develop нет)
make branches REPO=~/work/project BASE=master
cargo run -p musubiko-cli -- info ~/work/project
cargo run -p musubiko-cli -- diff feature/x ~/work/project        # файлы ветки и конфликты
cargo run -p musubiko-cli -- conflicts feature/x ~/work/project   # где слияние даст конфликт
cargo run -p musubiko-cli -- hotfix "LT-1 fix" ~/work/project --after worktree        # план
cargo run -p musubiko-cli -- hotfix "LT-1 fix" ~/work/project --after worktree --run  # выполнить
cargo run -p musubiko-cli -- radar ~/work/project                     # радар хотфиксов
```
