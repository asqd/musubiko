## Hotfix flow команды

- `hotfix/<имя>` — от свежего `origin/master`;
- `hotfix/<имя>-dev` — от свежего `origin/develop`, то же имя с суффиксом `-dev`;
- исправление попадает в обе ветки, в `-dev` — через cherry-pick.

## Этап 1. Ветки — сделано

- [x] Ядро: чтение веток через `for-each-ref`, локальные и удалённые копии, не запушенное.
- [x] Статусы: слита, слита через squash/rebase, конфликт (через `merge-tree`), не слита.
- [x] Хотфиксы сравниваются со своей базой, пары рядом.
- [x] Приложение: открытие репозитория, недавние, экран «Ветки» с фильтрами и поиском.

## Этап 2. Дифф как на GitHub — сделано

- [x] Дифф ветки от merge-base (как в pull request): дерево файлов, unified и split.
- [x] Подсветка синтаксиса (highlight.js) и изменённой части строки, разворот скрытого контекста.
- [x] Отметки «Просмотрено» (снимаются, если файл снова изменился), скрытие пробельных (`-w`),
      переименования, бинарные файлы, большие и сгенерированные файлы свёрнуты.
- [x] Вкладка «Коммиты»: дифф одного коммита. Вкладка «Конфликты»: места конфликтов из
      `merge-tree` — что в базе и что в ветке.
- [ ] Пословная подсветка вместо общего префикса и суффикса.
- [ ] Ленивая отрисовка очень больших диффов (сотни файлов).

## Этап 3. Hotfix flow — сделано

- [x] «Новый hotfix»: имя из номера задачи и текста, обе ветки от свежих `origin/*`, push.
- [x] Незакоммиченные изменения: worktree (по умолчанию) или stash и переключение; или только ветки.
- [x] Перед запуском — точный список команд; выполнение по шагам, остановка на ошибке,
      «Повторить», «Откатить», «Оставить как есть».
- [x] Проверка, что имя не занято локально и на `origin` (`ls-remote` перед созданием).
- [x] Журнал операций с отменой. Отмена защищена: ветку с новыми коммитами не удалит, ветку на
      сервере удаляет через `--force-with-lease`, чужой stash не вернёт.
- [ ] Проверка доступа к `origin` до начала (сейчас это делает шаг `fetch`).

## Этап 4. Радар хотфиксов — сделано

- [x] Сверка пар по patch-id и по содержимому (squash-слияния): что из master-части не
      перенесено на сторону develop. Коммиты хотфикса находятся и после слияния в master.
- [x] Тревога: коммиты в master, которых нет в develop (и хотфикс без `-dev`, уже влитый в master).
- [x] Перенос cherry-pick во временном worktree: ветка двигается только после успешного переноса;
      создание недостающей `-dev` ветки; push. Отмена через `update-ref` и `--force-with-lease`.
- [x] Удаление завершённых пар (локально и на `origin`) с возвратом из журнала.
- [x] Распознаёт репозитории без живого develop и не поднимает ложную тревогу.

## Этап 5. Гигиена веток — сделано

- [x] Выбор веток в списке (с учётом фильтра) и массовое удаление: локально и на `origin`
      одним атомарным push с `--force-with-lease`; возврат из журнала.
- [x] Фильтр «Удалены на сервере»: локальные ветки, чей upstream исчез после мержа.
- [x] «Получить» — `git fetch --prune` со временем последнего обновления.
- [x] Предупреждения: не слитые ветки, чужие ветки на сервере; базовые и текущая не удаляются.

## Этап 6. Удобство

- [x] «Где коммит?»: поиск по хэшу, номеру задачи (и в названиях веток) или тексту; есть ли
      коммит в master и develop — сам, как cherry-pick или по содержимому; с какого тега;
      в каких ветках; куда его перенесли через `cherry-pick -x`; перенос, если он только в master.
- [x] Checkout с выбором worktree или stash; ветка только на сервере получает локальную копию;
      при возврате на ветку предлагает вернуть изменения, убранные в stash при уходе с неё.
- [x] Палитра команд ⌘K: действия, разделы, недавние репозитории, дифф и checkout любой ветки,
      хотфиксы из радара, «Где коммит?» для введённого текста; нечёткий поиск, недавние сверху.
- [x] Конфликт при переносе: временная папка рядом с репозиторием, список файлов с маркерами,
      «взять из ветки / из коммита», «Проверить и продолжить» (сам делает `git add` и
      `cherry-pick --continue`), «Пропустить коммит», откат в любой момент.
