Возможности Установка GitHub ENRU

Ветки, их статусы и hotfix flow в одном окне

Git-клиент, который показывает, какие ветки уже слиты, даже если их вливали через squash, и где при слиянии будет конфликт. Подойдёт любой репозиторий, хоть с одной веткой main. А если у вас master и develop, Musubiko ещё проследит, чтобы хотфикс попал в обе.

статусы

Какие ветки уже слиты

Каждую ветку Musubiko сравнивает с базой: с develop, master (или main) или любой другой веткой, которую вы выберете. Master, main и develop берутся с сервера, так что «слита» означает, что изменения уже на сервере, а не только у вас локально.

  • слитавсе коммиты ветки уже есть в базе
  • слита · squashкоммиты другие, но изменения уже в базе; git branch --merged такие ветки не находит
  • конфликтпри слиянии будет конфликт, и видно, в каких файлах
  • не слитав ветке есть изменения, которых нет в базе

Слияние проверяется через git merge-tree --write-tree, рабочую копию и индекс оно не трогает. Результат кэшируется, пока не сдвинется ветка или база, поэтому в репозитории на 840 веток список при повторном открытии строится за 0,1 с.

дифф

Дифф ветки и конфликты до слияния

Дифф считается от места, где ветка отошла от базы, как в pull request на GitHub. Есть дерево файлов, режимы unified и split, подсветка изменённой части строки и отметка «Просмотрено».

Если ветка конфликтует с базой, можно открыть сами места конфликта и сравнить, что в базе и что в ветке.

хотфиксы

Хотфикс сразу в master и develop

Вы пишете название задачи, например «Project-4900 ошибка в документах», и Musubiko создаёт две ветки: hotfix/PROJECT-4900-oshibka-v-dokumentah от свежего master и …-dev от свежего develop. Перед этим он проверяет, что такие имена не заняты на сервере, а потом пушит обе. Команды можно посмотреть до запуска. Если develop в репозитории нет, хотфикс будет одной веткой от master.

В разделе «Хотфиксы» видно, какие исправления из master уже попали в develop. Коммит засчитывается, даже если его перенесли через cherry-pick или squash. Если чего-то не хватает, это можно перенести прямо оттуда.

поиск

Где коммит?

Искать можно по хэшу, номеру задачи или тексту сообщения. Для каждого найденного коммита видно, есть ли он в master и develop, с какого тега он в master, в каких ветках лежит и куда его переносили.

отмена

Любое действие можно отменить

Musubiko записывает каждое своё действие в журнал вместе с тем, как его отменить. Перед отменой он проверяет, что с тех пор ничего не изменилось. Например, ветку, в которую успели закоммитить, отмена не удалит, а ветку на сервере удаляет только через push --force-with-lease.

Если удалить неслитую ветку, её коммиты не пропадут: на них остаётся ссылка refs/musubiko/deleted/…, пока удаление можно отменить.

ещё
  • Мои ветки. Только ваши ветки. Сверху те, с которыми что-то не так: конфликт, база сильно ушла вперёд, есть незапушенные коммиты или неделю нет новых коммитов.
  • Уборка веток. Отметьте слитые или удалённые на сервере ветки, и Musubiko удалит их и локально, и на сервере одним push.
  • Checkout без stash. Если есть незакоммиченные изменения, ветку можно открыть в соседней папке через worktree.
  • Палитра ⌘K. Почти всё делается с клавиатуры: «checkout 4888», «дифф sitemap», хэш или номер задачи.
  • Обычный git. Все операции выполняются через git CLI, поэтому работают ваши настройки, хуки и доступы. Пока Musubiko только читает репозиторий, он не блокирует индекс и не мешает git в терминале.
  • Отчёт об ошибке. Кнопка копирует версии, текст ошибки и лог, и это можно сразу отправить в чат. Домашняя папка и токены в отчёте скрыты.
установка

Установка

Установщики — на странице релизов. Везде нужен git 2.38 или новее. Если хотите использовать конкретный git, укажите путь к нему в MUSUBIKO_GIT.

macOSMusubiko_<версия>_universal.dmg
Приложение подписано ad-hoc, без Apple Developer ID. В macOS 15 откройте его, закройте предупреждение и нажмите «Всё равно открыть» в «Системные настройки → Конфиденциальность и безопасность». В macOS 12–14 достаточно правого клика и «Открыть».
WindowsMusubiko_<версия>_x64-setup.exe
SmartScreen предупредит о неизвестном издателе: нажмите «Подробнее», затем «Выполнить в любом случае». Права администратора не нужны.
Linux.AppImage или .deb
Нужен WebKitGTK 4.1 (Ubuntu 22.04+, Debian 12+).

Из исходников

Понадобятся Rust 1.88+, Node.js 20+, а на macOS ещё Xcode Command Line Tools.

git clone https://github.com/asqd/musubiko
cd musubiko
make run      # собрать Musubiko.app и запустить
make test     # тесты ядра на временных репозиториях

То же самое можно посмотреть в терминале через утилиту musubiko:

cargo run -p musubiko-cli -- branches ~/work/project
cargo run -p musubiko-cli -- where PROJECT-4888 ~/work/project
